# 冻结Moirai的完整现有队列历史长度诊断

目的：先判断96点历史是否是偏弱的基线、增长历史的收益是否在4096点附近趋于
饱和，再讨论检索是否有额外价值。实验固定Moirai权重与96点预测长度，
比较96、512、2016、4096点历史，不训练网络、不修改当前固定5+5默认入口。

## 样本与因果边界

使用原已冻结的七数据集VAL/TEST队列中的全部查询，不再只抽首、中、末三个起点。
这些队列本身是既有抽样窗口，并非每个可能起点的滑窗穷举。
所有历史长度使用相同的、具有完整有限4096点历史的共同队列。
历史起点t的预测边界为t+96；长度L输入严格是`[t+96-L, t+96)`，
目标严格是`[t+96, t+192)`。不填补缺失或跨有效区间。

记录因4096点上下文不可用而排除的数量。逐个核对原始序列哈希、当前96点
历史和真实目标；归一化指标只使用原TRAIN标准差。新增长历史输入只读取
目标变量，不读取相关变量或当前真实未来。

## 选择与测试

主策略以整个VAL上的原始MSE最小选择一个长度，并列选择更短的长度。
不以TEST选择长度，也不按TEST在方法间拼接数据集赢家。
另有明确标为次要诊断的稳健策略：选择四个VAL时间块中最差相对96点MSE
最小的长度。主、次策略都对每个数据集在TEST前固定。

顺序为：准备并推理全部数据集VAL → 保存全部选择与哈希 →
才准备新增TEST输入、推理与评分。所有长度的TEST结果都保留，用于展示曲线；
部署候选严格是事先选定长度。原固定5+5也在同一TEST共同队列上重新评分。

TEST按唯一历史起点分四个连续块，报告每块MSE、MAE与TRAIN尺度NMSE。
这是一套固定策略在四个后续时期上的表现，不是四个重新训练/调参的外层折。
验证选择仅优化原始MSE，没有把MAE和NMSE伪装成同时保证不退化的目标。

## 饱和与不确定性

对4096相对2016的MSE变化，按同步日历周分组重采样计算探索性95%区间。
预先固定1%的实际差异范围：

- 整个区间落在[-1%, +1%]：在本模型、本队列和本尺度下接近这个范围内的持平。
- 点估计至少改善1%且区间下界大于0：4096仍带来改善。
- 区间上界小于0：4096比2016差，不能把它等同于“没有更多历史信息”。
- 其余：证据不足，不能宣称饱和。

这些区间没有校正多数据集、多轮探索，也不能保证周之间完全独立。
既有TEST已多次查看，因此本轮不是全新的盲测。

历史长度曲线只能检验一个信息来源：更多连续历史。即使持平，也不能证明
相关变量、外部已知条件或远期案例没有信息，更不能据此将剩余误差归于混沌。
本轮不额外训练多变量头、校准器或检索模型；它们仍需独立的容量匹配诊断。

## 执行与恢复

```powershell
.venv-moirai-gpu/Scripts/python.exe -m v7.benchmark_history_length --output v7/runs/history_length_new --batch-size 64
.venv-moirai-gpu/Scripts/python.exe -m v7.benchmark_history_length --output v7/runs/history_length_new --batch-size 64 --resume
.venv-moirai/Scripts/python.exe -m unittest v7.tests.test_history_length -q
.venv-moirai/Scripts/python.exe -m v7.verify_history_length --root v7/runs/history_length_new
.venv-moirai/Scripts/python.exe -m v7.report_history_length --root v7/runs/history_length_new
```

每个数据集、区间、长度完成后保存预测与来源哈希。恢复只重用经过哈希校验的
相同队列预测，不覆盖已有选择。96点预测复用固定缓存，并在真实GPU上抽查；
4096等长度使用同一固定权重的官方递归预测接口。

原始数据、预测、指标、模型缓存与本地报告均不发布。

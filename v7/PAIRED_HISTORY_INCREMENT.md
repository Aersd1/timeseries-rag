# 检索历史与后续序列成对输入：独立基线上的增量验证

本实验保持96→96、100候选、未来0.8/历史0.2重排、5+5案例以及原先的
固定初始案例库。复用已核验的forward_selector管线全部索引与Moirai缓存，
不同时更换编码器、案例数量或滚动记忆。Moirai保持冻结；案例历史输入的是
外部增量网络，不是作为额外上下文重新送进Moirai骨干。

## 输入与历史通路

每个查询输入当前96点历史、Moirai九分位预测、已观测64→32回测误差、
状态信息及独立基线预测。每条旧案例输入完整历史96点和其已发生后续96点。
后续片段每8点构成一个预测时段，同时保留已知真实数值、同一冻结Moirai
对它的预测、以及二者残差。因此输入不是仅有一段未来残差。

完整历史96点经过96→64→32的网络编码。该向量既进入案例注意力的键，
也与每个后续时段的向量拼接，进入预测值分支。历史不是仅用于检索打分。
序列使用已有的历史拟合幅度对齐；历史水平、幅度、趋势、年龄、日内及
周内相位差同时作为13维状态元信息保留。数值归一化和限幅不减少采样点数。

旧案例必须满足`case_start + 192 <= query_history_start`，不与查询的历史
或待预测区间重叠。第一路五个重排案例和第二路五个原始历史案例都满足该
规则；第二路内部另保持192点间距。训练、验证、测试使用同一规则。

## 独立基线与成对增量

复用上一轮每个TRAIN前缀独立拟合的query_only专家作为适配基线候选。
它不读取检索案例，权重在训练本轮增量网络前冻结。另保留直接Moirai模式。
增量模型在TRAIN对两种基线等概率训练，显式输入基线预测及模式标志，
避免事后选出基线后再倒用VAL训练增量模型。

对于基线B、案例R，同一网络计算：

```
delta = bounded(tanh(F(query, R)) - tanh(F(query, empty)))
candidate = B + delta
forecast = B + adopted_patch * strength * delta
```

空参考将全部案例的历史、后续、元信息和有效标志移除，查询本身保持不变。
同权重相减使空参考增量严格为零；训练中同时计算空分支，对其输出施加
0.01平方惩罚。训练还包含25%整组参考移除、10%历史模态移除、10%后续
模态移除及10%逐案例移除，使这些输入缺失状态在训练中出现。

增量限制沿用按Moirai分位数宽度和当前历史尺度构造的修正半径，不修改
Moirai预测本身。五个输入组分别独立训练，结构、种子和预算相同：32宽、
种子13、16轮、批256、AdamW学习率0.001、权重衰减0.001。
损失为等权的TRAIN尺度原始MSE与逐变量标准化MSE，加0.02加权MAE、
0.001增量能量和0.01空分支能量。它不是Moirai骨干的微调实验。

这个结构约束不自动证明检索有额外信息：非空参考仍可能为查询网络提供
额外计算路径，因此还必须与独立训练的随机、错配及历史输入消融比较。

## 前推与基线选择

沿用TRAIN约35%、60%、80%、100%四个截止点。各截止点上独立冻结已有
query_only基线，再拟合新的五组增量专家，预测下一段。训练标签全部结束
于截止点，前推查询历史开始于截止点之后。三段前推预测供收益选择器训练，
不使用增量专家在拟合行上的误差训练收益选择器。

限制：增量专家拟合时，适配基线在同一个TRAIN前缀上拟合，其在增量拟合行
上的预测是拟合内预测；这不是对基线的第三层交叉拟合。旧案例误差的参照
仍是同一冻结Moirai。前推收益标签才来自完整未参与当时拟合的后续时间段。

VAL按同步起点分为四段，清除跨边界192点标签。前两段仅比较直接Moirai与
原始query_only适配输出，决定基线模式；不根据任何RAG组的成绩选择基线。
若选择适配基线，后两段只确认，拒绝时整体回退Moirai并关闭RAG，不再另挑
一个基线或模型家族。若前两段选择直接Moirai，各增量组仍可尝试改善Moirai。

每个增量组、每种基线分别用完整前推队列训练三个32宽收益/风险小网络，
种子13/41/73、20轮。标签是相对相同B的逐8点MSE增益，而不是相对原始
Moirai的整网收益。只在该队列拟合输入标准化和目标尺度。

对每种基线事先分别训练选择器，VAL不会反向改变训练队列或归一化。
VAL前两段选择阈值、强度、风险及分歧惩罚，同时比较静态强度策略；
后两段只确认此前按校准目标选出的策略，不依据确认结果换另一个策略。
拒绝RAG的时段精确返回选定基线B。主组固定为paired。

另预先定义固定B为直接Moirai的次要对照，对所有数据集统一评估已有模式0
专家和模式0验证策略，避免适配基线的退化掩盖检索本身的作用。它不改变
主输出，不按TEST逐数据集换基线，也不重新校准。完整核验时若根目录存在
SECONDARY_DIRECT_MODE_PROTOCOL.json声明，会另存direct_mode输出与指标。
若复现实验需要该次要对照，应在首次TEST之前创建该声明；最小内容为
`{"mode": 0, "primary_unchanged": true}`。不能看完TEST后再选择是否报告它。

## 消融的准确含义

| 组 | 增量网络读取的案例信息 |
|---|---|
| paired | 完整96点历史、状态元信息、96点真实后续、冻结预测与残差 |
| history_only | 历史96点和历史状态；后续数值、冻结未来预测、残差均移除 |
| without_history_sequence | 历史96点和状态元信息移除；其余后续输入固定相同 |
| deranged | 历史与状态不变，各五案例内完全打乱整套后续/预测/残差 |
| matched_random | 状态匹配随机案例的完整历史及后续，独立训练同结构模型 |

without_history_sequence不是完全清除历史信息：固定后续表示仍经过旧历史
均值和幅度对齐，检索选择本身也依赖历史。history_only同样复用未来感知
检索选出的案例，不能称为去除旧未来对案例选择的所有影响。空参考基线
才完全不读取任何旧案例数值。随机案例继承原实验集合多样性的限制。

另对真实专家执行同权重干预：保持采用位置和强度固定，分别清除全部参考、
清除历史与状态、仅错配96点历史序列、清除后续输入、错配后续配对或换成
匹配随机案例。历史序列错配保留元信息与后续，用来检查模型是否实际依赖
历史采样点。输出变化证明依赖，不能单独证明该依赖有助于泛化。

## 评价与运行

完整TEST与旧稀疏TEST分别报告。除相对Moirai，还必须比较相对选定不检索
基线B的收益、真实相对历史/后续消融及错配/随机的配对收益。稳定性沿用
按周同步时间块95%区间下界大于0且四段连续测试期均改善。三个选择器种子
不是三次独立上游实验。既有TEST已多轮查看，结果属于探索性验证。

```
pip install -r v7/requirements-forward-selectors.txt
python -m v7.benchmark_paired_history_increment --forward <forward-root> --output <new-root> --datasets <names> --stage fit --device cuda
python -m v7.benchmark_paired_history_increment --forward <forward-root> --output <new-root> --datasets <names> --stage test --device cuda
python -m v7.verify_paired_history_increment --root <new-root> --datasets <names> --device cuda
python -m v7.verify_paired_history_increment --root <new-root> --datasets <names> --device cuda --deploy --live
```

默认all阶段先完成全部指定数据集的训练与VAL策略锁定，再加载其TEST。
完成阶段不可覆盖；协议、源索引、模型和输出均校验哈希。
部署接口为query_paired_history_increment.PairedHistoryPredictor，内部使用
物理截断的已观测存储重检索，接收历史而不接收当前真实未来。返回案例
历史/后续点数及采用标志，不把输入十条案例等同于十条均已证实有用。
Illness不满足沿用的共同前推长度协议，不伪造同条件成绩。

只发布代码、测试和机制说明；数据、案例、权重、预测、指标和报告留在本地。

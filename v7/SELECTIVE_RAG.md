# 逐窗口、分时段的RAG收益选择

本实验保持原100候选、原重排参数、原5+5案例以及96→96任务。
新增选择器判断某次预测的某个8点时段是否值得采用案例修正。
主输出固定为`real`，不根据每个数据集的TEST结果改换组别。

## 决策和退出

选择器对每个查询的12个预测时段估计修正收益、退化幅度和有利概率。
三个固定种子网络的收益均值减去半倍预期退化与一倍种子间标准差，形成
保守的采用分数。概率头提供辅助监督，不单独决定采用。

```
forecast = frozen_Moirai + enabled_patch * strength * (candidate - frozen_Moirai)
gain_label = MSE(frozen_Moirai, truth) - MSE(candidate, truth)
```

标签按该变量TRAIN标准差平方归一化。训练同时兼顾变量平衡与原始尺度总体
误差，回归收益和负收益幅度，另以辅助二分类损失监督收益符号。
三个网络均为两层32宽GELU，种子13/41/73，固定40轮，AdamW学习率0.002、
权重衰减0.01。所有组结构、种子和轮数相同。

拒绝时精确返回原始Moirai，不保留之前的查询修正头。查询修正本身是否有用
由独立的`query_only`对照检验，不能把它隐含放在拒绝分支。

## 输入与时间

输入包括当前已观测历史状态、Moirai分位数、64→32已观测回测误差、
候选修正幅度、案例历史距离和残差分歧，以及同一变量此前已经完整发生的
96→96预测的误差与增益。历史能力特征仅使用完整192点结束于当前历史
开始前的记录，最多最近8条。TEST期间不更新这个能力库，只使用冻结的
旧VAL历史。当前查询真实未来不是网络输入。

query_only不读取案例，history_only不读取案例真实未来。两组保持同样输入
维数；缺少的案例残差信息由已经观测的查询回测误差信息或零特征替代。

原预测专家仅在TRAIN拟合。选择器不使用专家在TRAIN上的拟合内预测误差，
而使用TRAIN之后已保存的旧VAL预测：按同步时间起点分为三段，第一段训练
选择器及其标准化，第二段选择阈值和强度，第三段只确认或拒绝。
完整192点标签必须结束于下一段历史开始前，边界不满足的样本清除。
确认段全部标签也必须结束于TEST历史开始前。

校准阈值网格为0、0.05、0.1、0.25、0.5、1、2；强度为0.1、0.25、0.5、1。
校准与确认均要求原始MSE、TRAIN标准化MSE和MAE不退化，并有实际MSE改善。
确认拒绝则整个组回退直接Moirai。按变量手工TEST修正不被允许。

这不是完全独立的全流水线确认：原检索、案例选择曾使用旧VAL，TEST也曾在
开发中查看。该限制仍存在。三段隔离只保证本次新选择器的拟合、校准、确认
与其后TEST的顺序；每个组在TEST前冻结参数和策略。不宣称预注册盲测。

## 对照

| 组 | 供选择器采用的预测 |
|---|---|
| query_only | 原冻结的仅查询网络输出 |
| history_only | 原冻结的仅案例历史网络输出 |
| real | 原冻结的真实5+5残差网络输出，固定主组 |
| shuffled | 原冻结的普通残差配对打乱网络输出 |
| matched_random | 原冻结的状态匹配随机案例网络输出 |
| deranged | 原冻结的全错配残差网络输出 |
| value_only | Moirai加0.25倍十案例平均残差，按历史尺度对齐并限幅；不含预测修正网络 |
| case_utility | 十个Moirai加0.25倍单案例残差的候选，选择器可逐时段选其中一个或全部拒绝 |
| case_random_utility | 同上，换成状态匹配随机十案例 |
| case_deranged_utility | 同上，各五案例组的残差完全错配，保留残差集合 |

前六组各有同预算的三个冻结预测专家和三个新选择器；后三个单案例组仅有
三个新选择器、相同十候选动作和相同训练预算。单案例组的训练记录数是
单候选组的十倍，不能声称这两类训练计算量相同。检索集合不变，十案例
不必全部使用，单个时段也允许不使用任何案例。

所有组还保留不做逐窗口选择的静态强度对照，使用同样校准与确认区间。
不能因新选择器在TEST更好而切换主输出，所有原始结果同时保留。

## 判断选择是否有效

1. 事后最佳选择只作为诊断：允许看真实未来，在直接Moirai与同候选/强度
   集合中选误差较小者。分别按完整窗口和8点时段计算。它是不可部署的
   乐观上限，不能用于训练、阈值选择或替代实际结果。
2. 同采用比例随机对照保持每个变量、每个预测时段的采用数量，随机打乱
   哪些窗口被采用，共200次。案例选择和强度仍附着原查询，隔离是否采用
   这一判断的价值。它是TEST描述性诊断，不是额外部署策略。
3. 报告采用比例、采用后改善/退化贡献、采用窗口中的获益比例与整体误差。
   全部拒绝仅表示避免了修正，不表示检索产生额外收益。
4. 风险—覆盖曲线按分数排序，展示强制采用不同比例时的误差。曲线使用
   原候选完整修正，仅用于描述，不能据此重新选择TEST阈值。
5. 有较大事后上限但实际无改善，只能说明当前选择器没有稳定兑现候选
   互补性。没有上限改善也只能否定当前候选，不能断言数据具有混沌性。

## 运行与审计

```
python -m v7.benchmark_selective_rag --source <unified-root> --output <new-root> --datasets <names> --device cuda
python -m v7.verify_selective_rag --root <new-root> --datasets <names> --device cpu
python -m v7.verify_selective_rag --root <new-root> --datasets <names> --device cuda
python -m v7.verify_selective_rag --root <new-root> --datasets <names> --device cuda --deploy
```

已完成目录不可重新训练或覆盖。参数、阈值、归一化和上游缓存均记录哈希。
审计重建全部策略和预测，核验所有案例时间边界，检查TEST未来污染不改变
候选和输入，以及拒绝时与原Moirai逐值一致。部署审计实际重放原检索与网络，
复用已核验的冻结Moirai预测；不冒充重新运行了Moirai骨干。

部署类为`query_selective_rag.SelectiveRagPredictor`，默认`arm='real'`。
补充输出`case_utility`或`value_only`必须显式指定。返回逐时段采用标记，
不把检索到十个案例当成十个都已发挥作用。选择器确认完成前的查询会拒绝执行。

只发布代码、测试、机制说明。数据、预测、案例、权重、分数、图表和报告保留本地。

# 未来状态检索机制的两条优化实验

这两条实现保持96点历史、96点预测、100个初始候选、5个案例，以及0.8未来兼容与0.2历史相似的先验。Moirai作为冻结的基础预测器；训练的是自身的未来状态编码器。它们是独立实验，不依据测试结果为各数据集挑选赢家。

## 案例提供可靠的局部信息

旧路由对完整96步选择一个专家与比例。`component_rag.py`增加两个独立对照。

首先，将对齐后的每个旧案例未来拆成16步块均值和块内细节。五个案例的加权细节均值作为信号，加权方差作为分歧。每个块的置信度为信号能量除以信号能量加分歧能量。案例起点的192点重叠程度还构成相关性矩阵；有效案例数为权重向量在该矩阵中的二次型的倒数。有效案例不足时下调置信度，相同事件的多个重叠窗口不能伪装成五个独立支持者。

细节专家保留编码器路径的块均值，仅将块内细节向案例一致的部分靠近。预设细节强度为0.25、0.5、1。保持块均值这一性质作用于未限幅的专家路径；后续分位跨度限幅可能改变最终块均值。它没有读取查询真实未来，也没有将基础预测误差重复减去。

其次，按六个16步预测时段选择修正。每个变量的验证样本仍按时间分成三块。前两块只能在当前旧路由的校准提议附近，搜索编码器、案例、混合或细节专家；要求两块各自MSE、MAE改善，并至少75%的窗口改善。局部替换强度固定为一半，使小验证集不至于支持完整更换。最后一块只确认或拒绝组装后的唯一方案，既要优于旧校准提议，也要优于旧路由最终回退方案；不能再搜索其他专家。

增加`segmented_no_rag`对照，使用同一个编码器、相同六时段路由与确认规则，只移除案例相关专家。基础适配器若已被最后验证块拒绝，新增路由也不能重新启用它。整段扩充专家和时段路由均独立报告，不把测试最佳方案拼成一个系统。

## 编码器保留更短的未来变化

`train_resolution`用8步历史块保留更细的历史形状，监督输出可以是8步或16步未来块。岭惩罚和表示粒度均在训练区间选择；两折拟合的完整192点训练案例必须在该折查询历史开始之前结束。

两种粒度不能直接比较不同维数的块均值损失。因此，将各自向前折预测插值回完整96点，再使用相同的历史波动尺度、相同真实未来计算完整96点误差，选择误差较低的粒度。相等时选16步。验证与测试不参与粒度选择。每个变量组仍由初始历史库相关性固定，不能使用测试相关性。

查询只根据历史预测这些状态；重排比较的是预测状态与已经发生完毕的旧案例未来状态。监督更细不等于允许读取当前真实未来。原型掩码按实际选择的粒度生成，缺失通道不当作已知未来。重排距离系数继续只由训练向前查询选择，后续采用策略沿用原验证规则。

每个版本都报告同编码器不使用检索的结果。更细的编码器本身可能提高预测，而RAG额外收益可能很小、为负，或在不同指标中方向不同。这些实现不保证普遍提升。

## 边界与复现

所有候选完整192点窗口必须在当前查询历史开始前结束，并处于初始历史库范围内。规则适用于训练、验证和测试。推理阶段其他变量也只读取当前同步96点历史。5个案例之间可以重叠，其冗余只降低置信度，不放松与查询的隔离。

`benchmark_component_rag.py`冻结策略后复用相同基础预测做配对比较；`query_component_rag.py`提供实际历史输入接口。`benchmark_resolution_rag.py`训练粒度实验，`query_future_state_rag.py`兼容旧16步检查点和新可选粒度检查点。

`verify_component_rag.py`重建验证策略、最终预测与指标，并核对部署接口。`verify_future_router.py`重新训练各编码器、重建粒度/距离系数/路由选择，审计候选时间边界；`verify_future_query.py`核对实际GPU推理。测试还覆盖保持专家块均值、案例分歧与冗余、最后验证块只能拒绝、被拒绝基础专家不能重新启用，以及细粒度能识别被粗均值抵消的可预测变化。

已查看过的测试时期只能用于探索，不能把换窗口、重复运行或更换模型称为新盲测。`evaluate_component_reference.py`会先固定模型与窗口引用，再用共同基础模型输出比较先前已报告的窗口；报告明确标记这种复用。数据、训练权重、指标和运行报告保留本地，仓库仅发布实现与机制说明。

```powershell
python -m v7.benchmark_component_rag --checkpoint-root <fixed-future-root> --output <component-root> --datasets weather
python -m v7.benchmark_resolution_rag --checkpoint-root <fixed-future-root> --output <resolution-root> --datasets weather
python -m v7.verify_component_rag --root <component-root> --datasets weather
python -m v7.verify_future_router --root <resolution-root> --rebuild-root <audit-root> --datasets weather
```

# 保留原始状态的召回与收益重排

## 解决什么信息缺口

原收益重排已经使用原始水平、幅度、趋势差、日内相位等59项输入。
但是它只能处理第一阶段进入的100个候选。如果第一阶段只比较标准化
波动形状，不同状态的窗口可能占据候选库，正确状态的案例则根本没有
机会进入重排。本实验把状态距离提前到召回，检验其额外贡献。

## 召回距离

基础预测仍由冻结的 Moirai 2 读取原始96点历史、输出96点未来。
召回形状沿用原方案：25点因果滑动均值去趋势，再以窗口自己的均值
和标准差标准化残差，比较96点均方距离 `D_shape`。

状态从原始历史计算，尺度只取初始25%历史库的变量标准差 `s`：

* 水平差：`((mean(candidate)-mean(query))/s)^2`。
* 幅度差：两个窗口的 `log(max(std(window), 0.1*s)/s)` 之差平方。
* 趋势差：历史窗口内最小二乘直线的首尾变化量之差，除以 `s` 后平方。
* 日内差：`1-cos(2*pi*(candidate_start-query_start)/period)`。

以上四项平均得到 `D_state`，最终距离为
`D_shape + state_weight * D_state`。索引周期按采样间隔换算：小时24、
15分钟96、10分钟144。周数据没有可辨认的日内相位，省略此项。
这些状态没有节假日标签，也没有读取查询的真实未来。

状态权重候选固定为 `[0, 0.05, 0.2, 1]`。权重0保持原始float32形状
距离及时间位置的并列排序，逐查询核对候选是否与原缓存完全一致。

## 如何选择权重、重排和预测

每个权重重新得到100候选，仍以原来的0.8未来兼容、0.2历史形状距离
作为重排先验。未来兼容比较的是 Moirai 预测分位数与已知旧案例后续，
不是真实的当前未来。状态距离只改变召回，不替换0.2中的历史评分。

候选修正值是旧案例当时 Moirai 的预测误差，除以初始历史库标准差。
收益重排仍使用原59项特征、岭回归和上限0.5的修正系数。模型训练标签
是当前训练查询误差与候选修正的内积，估计使用修正后MSE会不会下降。
选择5个候选并加权后，预测为 `raw_moirai + beta * correction * s`。
这是基础模型外部的误差适配机制，不是Moirai内部微调。

权重和岭惩罚共同通过训练区间的两次向前验证选择。每次拟合样本的
完整192点窗口结束后，才允许开始后面的验证查询；所有同文件变量
共享这个时间边界，减少相关变量的时间泄漏。最终验证和测试不选权重。

每变量验证分成三块：前两块选择beta，要求都改善且平均至少改善1%；
第三块只确认或拒绝，不能重新选择beta。测试未来仅计算指标。
状态权重0、beta0或最终不改善，都不能被描述为新检索机制有效。

候选完整历史加后续必须结束于查询历史开始前，包括训练查询。
初始历史库固定，不将测试期观测加入库。查询自身及重叠192点案例排除。

## 对照和跨数据集评估

配对报告四个输出：直接Moirai、原0.8/0.2排序加稳定回退、收益重排加
稳定回退、状态召回加收益重排。相同数据集的四个方案共用模型预测、
查询窗口、候选库、100候选和5个辅助案例。

ETT复用原96→96缓存，历史库索引步长1。其他数据集覆盖全部变量，
为了控制计算量，历史库统一步长16，每变量最多32个随机训练窗口、
12个均匀分布的非重叠验证窗口、12个均匀分布的非重叠测试窗口。
抽样只依据时间位置及固定种子，发生在任何模型预测之前。
两种索引/抽样协议分开标注，不据此作跨数据集绝对分数排名。

illness周数据的25%历史库只包含50个完整96→96案例，验证/测试各只有
一个完整窗口，不满足100候选和三块独立验证。程序报告直接预测和
不适用原因，不伪造检索指标。缩短窗口或另设切分需要另立实验协议。

NMSE以初始历史库各变量方差归一化；同时保存原始MSE/MAE。
测试区间此前可能用于方案开发，单种子、窗口抽样和自定义切分属于
探索性评估。不能承诺状态召回或任何其他方案必然超过基础模型。

## 运行

```powershell
python -m v7.prepare_state_benchmark --output v7/runs/state_raw_other_96_20261013 --datasets illness weather electricity traffic
python -m v7.benchmark_state_recall --cache v7/runs/state_raw_other_96_20261013 --output v7/runs/state_recall_96_20261013 --datasets illness weather electricity traffic
python -m v7.benchmark_state_recall --cache v7/runs/rag_error_correction_96_20261013 --output v7/runs/state_recall_96_20261013 --datasets ETTh1 ETTh2 ETTm1 ETTm2 --baseline v7/runs/benefit_rerank_96_20261013/rag_error_correction_96_20261013
python -m v7.verify_state_recall --root v7/runs/state_recall_96_20261013
python -m v7.verify_state_query --root v7/runs/state_recall_96_20261013 --datasets ETTm1 weather electricity traffic
python -m v7.diagnose_state_recall --root v7/runs/state_recall_96_20261013 --check-electricity
python -m unittest v7.tests.test_state_recall v7.tests.test_benefit_rerank
```

原始缓存生成支持按变量恢复，恢复时核对参数契约与文件哈希。基准输出
不会覆盖已有未完成目录；更改参数应使用新的输出路径。最终权重和
模型参数保存在本地，由 `query_state_recall.py` 读取并仅接收96点历史。
测试会核对批量加速的收益选择与旧逐查询实现一致，防止性能改写改变
实验机制。原实现文件不需要修改。发布仅包含代码、测试和机制说明，
数据、模型参数、缓存和实验分数均保留本地。

如果平均NMSE受到极端尺度变化主导，诊断程序会补充逐变量NMSE中位数、
改善/退化/持平变量数，并核对最大误差变量的原CSV与缓存和时间间隔。
这个事后诊断不删除变量，不改变训练或采用策略，也不替换主指标。
